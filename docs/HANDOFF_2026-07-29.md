**The rule that caused trouble once already:** a *concept* DOI always points at the newest
version, a *version* DOI is frozen forever. Use the concept DOI when you want a link that stays
current (README, CITATION.cff). Use the version DOI when you are naming a specific historical
state (an erratum, a "this is the code that produced these numbers" claim). Getting this backwards
means either misdirecting readers or citing code that cannot reproduce your results.

## 3. The Biondi exchange

Dr Filippo Biondi commented publicly (YouTube, on a video where the preprint had been linked)

His objections reduced to three suggestions about processing choices the paper had not varied:
sub-aperture window function, coregistration estimator, and floating-point precision.

**Response:** a 96-configuration sensitivity sweep (`src/sensitivity_sweep.py`) crossing
4 windows × 3 coregistrators × 2 precisions × sites. Full write-up in
`docs/SENSITIVITY_RESPONSE_BIONDI.md`. A public reply has been posted; drafts at
`docs/reply_final.md` and `docs/reply_short.md`.

**Were his suggestions new information?** No. None of window, coregistrator, precision or
sub-aperture count is disclosed in the 2022 paper, the patent WO2024008365A1, or the 2025
presentations. They are undocumented degrees of freedom, which is itself part of the problem: a
method whose result depends on four undisclosed knobs cannot be independently reproduced.

## 4. What the sweep found — including the error it found in our own paper

**The reproduction check.** At the pipeline default (n_sub = 11, Hann, phase correlation, float64)
the sweep reproduced the published table exactly for two sites: Butte 3.33× against a published
3.3×, Vesuvius 4.11× against 4.1×. **Komati did not reproduce.**

**The Komati error.** That row had been computed at `n_sub = 128`, not the default 11, and its
verdict label was wrong for that setting. Corrected: **2.8× / 1.3×, ratio 2.15** against the
published **50× / 10×, ratio 5.00**. Full erratum: `docs/ERRATUM_KOMATI.md`.

The correction *improves* the paper. 50/10 is a ratio of exactly 5.0, sitting precisely on the
manuscript's own `> 5×` decision rule — the single most attackable row in the table. At 2.15 it is
comfortably below threshold. Under the alternative reading, taken at face value as an `n_sub = 128`
run, the correct label is *surface-pinned artifact*, which is also not a detection. **No claim in
the abstract, discussion or conclusion changes.**

**Two further weaknesses, deferred to revision** because unlike Komati they affect every row:

1. **The surface-pinning guard** used a threshold of 5% *of the depth axis*. The physical meaning
   of that threshold changes with `n_sub`, because the axis extent scales with the sub-aperture
   count while the bin count stays fixed. Replaced by an absolute depth in resolution cells
   (`pinned_absolute`).
2. **The null test** shuffled sub-aperture order, which destroys the look-to-look smoothness that
   80% spectral overlap guarantees *even under pure noise*. That makes it anti-conservative — too
   easy to beat. Replaced by an alignment null (`alignment_null`) that preserves each patch's depth
   profile and randomises only cross-patch agreement.

Both changes **strengthen** the negative result. Under the corrected pair the sweep returns zero
detections where the original pair returned some.

## 5. Bingham Canyon — new, 29 July, not yet in the paper

Table 2 currently lists Bingham as `0.67 / front-end only / no signal / n/a`. That understates what
we have, and the corrected guard changes the answer.

Scene `2024-01-12-04-09-18_UMBRA-05_SICD.nitf`, n_sub = 11, Hann, phase correlation,
fixed comparison window 0–11.6 m, `dz_phys` = 2.11 m:

| quantity | value |
|---|---|
| contrast (native and fixed-window) | **3.87** |
| shuffle null | 1.47 → C/shuf **2.64** |
| **alignment null** | 1.62 → **C/align 2.40** |
| peak depth | **3.5 m** |
| old 5%-of-axis guard | **clear** |
| **new absolute 2-cell guard (4.2 m)** | **PIN** |
| detections at > 5× | **0 / 1** |
| positive control | PASS |

**Verdict: surface-pinned artifact.** Not a clean null — the same category as Butte.

Two things follow.

**First, do not upgrade the Bingham row to "null".** An earlier reading of the cached sweep
(`runs/sweep_bingham.json`) showed `surface_pinned: False` and suggested Bingham could become a
fifth clean null. That was the *old* guard on the n_sub-dependent axis: 5% of an 11.6 m axis is
0.58 m, so a 3.5 m peak passed. The absolute two-cell rule is 4.2 m, and the same 3.5 m peak fails.
Same peak, opposite verdict.

**Second, Bingham is now the cleanest available demonstration of why the guard change matters.** It
is a row the old guard called clear and the new guard calls pinned, on real data, with the
positive control passing. That is a stronger argument for the guard replacement than any synthetic
example. It belongs in the revision.

Be careful with one number in public: under the *shuffle* null Bingham comes back at z = 12,
p = 0.005. That is the anti-conservative null being replaced. Quoted without context, "z = 12"
reads as a detection. Always pair it with the alignment-null figure of 2.40 and the > 5× rule.

## 7. Environment gotchas that cost time

- `reportlab` is not installed system-wide and disappears between sessions. When the PDF build
  fails with `ModuleNotFoundError: No module named 'reportlab'`, run
  `python3 -m pip install reportlab` and rebuild.
- The bridge VM used by the assistant has numpy but **no scipy and no network**, so
  `sensitivity_sweep.py` and `followup_experiments.py` cannot run there. They must be run from a
  real Terminal on the Mac.
- Git operations through the bridge leave stale `.git/*.lock` files that cannot be deleted from
  that side. They get moved to `.git/_stale_locks/`. Harmless, but that directory will accumulate.
- Zenodo had a platform-wide file-upload outage 28 Jul 23:00 UTC – 29 Jul 08:15 UTC. If an upload
  fails, check Zenodo's status banner before assuming it is a local problem.

## 9. Things to be careful about

- **Never claim the paper disproves structures under Giza.** It shows the *method* cannot see them
  and manufactures them on known-empty ground. That distinction is the whole credibility of the work.
- **The AI disclosure is in the manuscript** and was disclosed at the original PCI submission. The
  manuscript states no AI system is listed as an author. Keep the git history consistent with that:
  commits are authored by Hassan Foreman, because rewriting them would contradict the paper's own
  disclosure in a live peer-review process.
- **The Komati error is now public** in the reply to Biondi. It is disclosed to the recommender. It
  is in the release notes. There is nothing left to get ahead of — answer questions about it
  directly and without defensiveness. Finding it yourself, before referees, is the strongest
